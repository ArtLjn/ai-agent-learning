## 1. 文档定位

本目录沉淀「基于多智能体协同的智能工单处理系统设计与实现」毕业设计的完整设计文档。

v2.0 起，项目从单一演示系统演进为**双项目协同架构**：

- **ai-agent-learning（主系统）**：FastAPI + LangGraph 工单处理 + 4 大角色模块的前端
- **rag-service（独立项目，待建）**：FastAPI + Qdrant 的可复用 RAG 服务，对内供主系统调用，对外可独立部署给其他项目复用

主系统内部按角色拆分为 **4 大模块共 30 个功能**（回应答辩反馈"模块要按角色分层 + 工作量不够"）：

1. **用户模块（8 个功能）**：登录账户、用户注册、用户信息管理、修改密码、工单提交、工单查询与详情、消息补充、满意度反馈
2. **管理员模块（7 个功能）**：人工审核工作台、知识库管理、知识库版本回滚、用户管理、决策采纳率统计、系统配置查看、操作日志审计
3. **开发人员模块（7 个功能）**：Trace 决策树、Prompt 版本对比、RAG 检索调试器、Token 成本控制台、Agent 调用统计、服务健康检查、配额管理
4. **智能算法模块（8 个功能）**：TicketIntentAgent、ClassifierAgent、ReActProcessorAgent、ReviewerAgent、CoordinatorAgent、LangGraph 编排、工具层（含 RAG Client）、决策追踪

完整功能编号清单（U-/A-/D-/I- 前缀）见 [assets/system-module-architecture-v2-ascii.md](./assets/system-module-architecture-v2-ascii.md)。

## 5. 毕设范围声明（v2.0 修订）

本项目定位为本科毕业设计。v2.0 起，从 v1.x 的「最小演示」策略转向**「系统性架构」**策略——回应答辩反馈"工作量不够，要么堆算法要么堆业务"，做以下扩展：

**v2.0 新增范围：**

- **rag-service 独立项目**：把 RAG 能力抽成独立服务，复用 NSQA 项目的 PDF 复杂文档处理架构，对外可复用。论文可独立成章。
- **4 大角色模块**：主系统按用户 / 管理员 / 开发人员 / 智能算法拆分，回应"模块要按角色分层"。
- **开发人员工作台**：Trace 决策树、Prompt 版本对比、RAG 检索调试器、Token 成本控制台（复用 farm-manager 项目资产）。

**v2.0 仍坚持的克制：**

- 不做多租户 / 真实支付 / 短信邮件 / SLA 排班 / 自训练模型。
- 不引入知识图谱（KG）—— 已与导师澄清"NSQA 是独立项目，本系统未用 KG"，KG 暂搁置。
- 数据库不做读写分离 / 分库分表 / 备份恢复等生产级治理。

详细边界见 [06_项目管理/02_毕设范围控制.md](./06_项目管理/02_毕设范围控制.md)。
