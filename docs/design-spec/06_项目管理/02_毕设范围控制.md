# 毕设范围控制

## 1. 范围控制原则（v2.0 修订）

本项目来自学习项目，已有内容较多。毕业设计应聚焦"智能工单处理系统"，避免把基础 Agent、论文阅读助手、个人知识库等学习模块全部纳入论文主线。

**v2.0 范围策略调整：**

- v1.x 阶段策略：**克制 demo**——只保留最小可演示链路。
- v2.0 阶段策略：**系统性架构**——回应答辩反馈"工作量不够、模块要按角色分层"，扩展为双项目 + 4 大角色模块。

新原则：

- 主系统按角色拆分为 4 大模块（用户/管理员/开发人员/智能算法），每个模块对应论文一个一级章节。
- RAG 能力抽离为独立项目 `rag-service`，论文可独立成章，对外可复用。
- 重点突出三大学术亮点：① 多智能体协同（智能算法模块）；② 复杂文档 RAG（rag-service）；③ 人机协同闭环（管理员模块）。
- 仍坚持不引入企业级业务复杂度（多租户/支付/SLA 等）。

## 2. 论文主线建议（v2.0 调整）

论文标题：基于多智能体协同的智能工单处理系统设计与实现。

v2.0 建议章节主线：

1. **绪论**：说明工单处理背景、多智能体和大模型应用价值。
2. **相关技术**：FastAPI、LangGraph、RAG、Cross-Encoder 重排、React、SQLAlchemy async、MySQL、Qdrant。
3. **需求分析**：4 大角色（用户/管理员/开发人员/算法）的功能与非功能需求。
4. **系统总体设计**：双项目架构 + 4 大模块协作。
5. **智能算法模块设计**：5 Agent + LangGraph 编排 + 决策追踪。
6. **RAG 服务设计**（独立章节）：PDF 复杂解析 + 混合检索 + 重排 + 评估。
7. **角色功能模块设计**：用户/管理员/开发人员三大业务模块。
8. **系统实现**：分类、处理、审核、人工审核、用户补充、Trace 调试、Token 控制等关键实现。
9. **系统测试**：单元测试 + 集成测试 + RAG 评估实验。
10. **总结与展望**：成果、局限、未来扩展（含 KG 融合展望）。

## 3. v2.0 新增范围与边界

### 3.1 新增范围（v2.0）

| 新增项 | 范围 | 工时估算 |
| --- | --- | --- |
| rag-service 独立项目 | 目录结构、API 契约、PDF 复杂解析（迁移自 NSQA）、混合检索、Cross-Encoder 重排 | 4-5 天 |
| 主系统 4 大模块重构 | 用户/管理员/开发人员/智能算法的源码与文档对齐 | 1-2 天 |
| 开发人员工作台 | Trace 决策树 + Prompt 版本 + RAG 调试器 + Token 控制台（复用 explore/） | 2-3 天 |
| RAG Client | `tools/rag_client.py` HTTP 客户端 + 降级策略 | 0.5 天 |
| 数据库扩展 | `prompt_versions`、`token_daily_stats` 表 | 0.5 天 |

**总工时：8-11 天**（v1.x 的克制策略压到 5-7 天，v2.0 扩展到 8-11 天，但仍可在毕设周期内完成）。

### 3.2 v2.0 仍坚持的克制（不做的内容）

| 不建议扩展 | 原因 |
| --- | --- |
| 多租户权限系统 | 工作量大，偏离多 Agent 主线 |
| 完整客服聊天系统 | 会变成 IM 项目 |
| 复杂 SLA 和排班 | 业务复杂度过高 |
| 真实支付、退款、短信邮件对接 | 外部依赖多，不适合毕设演示 |
| 大规模分布式部署 | 与本科毕设重点不匹配 |
| 自训练模型或微调 | 成本和风险较高 |
| **知识图谱（KG）** | 已与导师澄清 NSQA 是独立项目，本系统未用 KG；KG 暂搁置，作为论文展望 |
| **GraphRAG 融合** | 同上，作为 v3.0 展望 |
| 数据库读写分离 / 分库分表 | 数据量小，单库够用 |
| 真实 OAuth / SSO | 用 session cookie 即可 |

## 4. v1.0 已纳入范围 vs 仍展望的内容

### v1.0 已纳入（人工审核闭环）

纳入部分（详见 [01_正式设计/09_人工审核工作台设计.md](../01_正式设计/09_人工审核工作台设计.md)）：

- 审核队列与决策 API。
- 工作流暂停 / 恢复机制（基于持久化状态，未引入 checkpointer）。
- 审核工作台前端页面。
- CoordinatorAgent 辅助决策建议。
- `human_reviews` 表持久化。
- 轻量登录鉴权。

### v2.0 已纳入（新增）

- rag-service 独立项目（PDF 解析 + 混合检索 + 重排）。
- 4 大角色模块重构。
- 开发人员工作台（含 Token 控制台，复用 explore/farm-manager）。
- RAG Client + 降级策略。
- `prompt_versions`、`token_daily_stats` 数据库扩展。

### 仍展望的内容（v3.0+）

- **GraphRAG 知识图谱融合**：在 rag-service 中加入 KG 抽取与图遍历检索，与向量检索并行融合。可借鉴 NSQA 项目经验。
- 审核员账户体系、技能组分配、SLA 超时、认领锁定、多人会签、工单转派链路、真实邮件/短信通知审核员。
- 多租户和权限控制。
- 引入更完整的 SLA 规则。
- 基于历史处理结果形成持续学习闭环。
- 数据库迁移体系、备份恢复和读写分离等生产级数据库治理。
- 更细粒度的安全审计。

## 5. 最小可交付版本（v2.0）

v2.0 最小可交付版本应包含：

- 主系统 4 大模块源码与前端页面。
- rag-service 可独立启动，提供 `/parse` `/ingest` `/retrieve` `/rerank` `/health`。
- 主系统通过 RAG Client 调用 rag-service，降级策略生效。
- 用户可提交工单，工单流转完整可演示。
- 管理员可审核、上传知识、查看用户。
- 开发人员可查看 Trace、调试 RAG、监控 Token。
- 测试用例覆盖核心流程。
- 文档齐全，论文主体章节可写。

## 6. v2.0 与 v1.x 范围对比

| 维度 | v1.x | v2.0 |
| --- | --- | --- |
| 项目结构 | 单项目 | 双项目（主系统 + rag-service） |
| 模块划分 | 6 层扁平（表现/接口/编排/Agent/工具/数据） | 4 大角色模块（用户/管理员/开发/算法） |
| RAG 实现 | 内部模块（personal_knowledge_base） | 独立服务（rag-service）+ HTTP 调用 |
| 算法深度 | 基础向量检索 | PDF 复杂解析 + 混合检索 + 重排 |
| 开发者工具 | 仅 trace 展示 | Trace 决策树 + Prompt 版本 + RAG 调试 + Token 控制台 |
| 工时 | 5-7 天 | 8-11 天 |
| 论文章节 | 7 章 | 10 章 |
| 复用资产 | 无 | farm-manager 的 Token 控制台、Trace 时间线 |
