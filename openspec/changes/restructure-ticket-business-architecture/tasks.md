## 业务架构整理

- [ ] 梳理系统业务目标：明确系统是“智能工单处理系统”，不是泛 RAG 平台、泛 Agent 平台或单纯知识库系统
  - 产物：业务目标说明，可直接放入论文系统概述和答辩讲稿
- [ ] 梳理工单生命周期：提交、预诊断、材料采集、分类路由、知识处理、质量审核、人工接管、用户补充、结果验收、申诉归档
  - 产物：主流程图和流程说明
- [ ] 梳理业务问题与系统解决方式：用户描述不规范、人工初筛成本高、常见问题重复处理、低质量自动回复、高风险需人工复核、过程不可解释
  - 产物：问题-功能-技术映射表

## 角色职责整理

- [ ] 明确工单提交人职责：发起服务请求、补充材料、查看进度、验收结果、申诉复盘

- [ ] 明确工单审核员职责：处理待审工单、核查 AI 建议、提交审核决策、请求用户补充

- [ ] 明确系统管理员职责：管理账号、知识、配置、日志和运营统计

- [ ] 明确开发运维人员职责：诊断分类错误、检索未命中、回答质量差、流程卡住、成本异常和服务健康问题
  - 产物：开发人员模块答辩说明
- [ ] 明确智能处理引擎定位：非登录角色，负责自动理解、处理、审核和状态流转
  - 产物：智能处理模块边界说明

## 用户侧功能补强

- [ ] 将登录、注册、会话、联系方式、偏好分类合并表达为“服务档案”
  - 目的：避免“身份认证与会话”“身份初始化”这类小模块显得体量不足
- [ ] 设计自助预诊断流程：用户提交前识别问题类型、紧急程度、风险提示和所需材料
  - 产物：预诊断页面/接口任务说明
- [ ] 设计智能提单流程：自然语言描述转结构化工单，支持标题、分类候选、影响范围、联系方式和缺失字段提示
  - 产物：提单页面/接口任务说明
- [ ] 设计材料采集流程：按分类采集订单号、支付流水、错误截图、设备环境、影响范围等信息
  - 产物：材料清单字段规范
- [ ] 设计进度协同流程：工单列表、详情、状态时间线、节点进度和处理依据展示
  - 产物：用户工单详情页任务说明
- [ ] 设计补充沟通流程：waiting_user_input 状态下提交补充材料并恢复处理
  - 产物：用户补充消息接口和状态恢复说明
- [ ] 设计结果验收与申诉升级流程：用户确认满意或触发人工复核
  - 产物：满意度反馈、申诉入口和历史复盘说明

## 智能处理能力凝练

- [ ] 提炼工单意图抽取方法：输入自然语言和服务档案，输出结构化字段和缺失字段
  - 说明：方法为 LLM 结构化抽取、Schema 校验、关键词兜底
- [ ] 提炼分类与风险识别方法：输入结构化工单，输出类别、优先级、风险标签和是否人工审核
  - 说明：方法为 LLM 分类、规则引擎、置信度阈值
- [ ] 提炼混合检索融合方法：输入问题、分类和上下文，输出候选知识片段和融合分数
  - 说明：方法为向量召回、BM25 关键词召回、RRF 融合
- [ ] 提炼重排方法：输入候选知识片段和原始问题，输出更高相关性的 Top-K 证据
  - 说明：方法为 Cross-Encoder 相关性评分
- [ ] 提炼知识增强生成方法：输入工单上下文和证据片段，输出处理方案、依据引用和下一步建议
  - 说明：方法为 ReAct 工具调用和受约束提示词
- [ ] 提炼质量审核评分方法：输入原始工单、处理方案和证据，输出评分、问题类型和重试/转人工建议
  - 说明：方法为 LLM 评审 Rubric 和阈值策略
- [ ] 提炼升级与恢复编排方法：输入分类结果、审核评分、重试次数和用户反馈，输出下一流程节点
  - 说明：方法为 LangGraph 状态机和条件路由
