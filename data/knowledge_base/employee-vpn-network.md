# VPN、办公网与远程办公

## 适用场景

- 员工远程办公时 VPN 连接失败。
- VPN 连接成功但无法访问内网系统。
- 办公区 Wi-Fi 慢、掉线、无法认证或无法访问打印机。
- 员工出差或居家办公需要临时访问内部资源。

## 常见原因

1. 密码或 MFA 验证失败。
2. VPN 客户端版本过旧或配置文件过期。
3. 员工未加入允许远程访问的用户组。
4. 本地网络、运营商 DNS 或代理配置异常。
5. 内网系统本身故障或访问策略变更。

## 员工自助步骤

- 确认账号密码和 MFA 可用。
- 切换网络后重试，例如手机热点。
- 更新 VPN 客户端并重新导入配置。
- 关闭个人代理、加速器或冲突的安全软件。
- 记录报错代码、访问地址和失败时间。

## 服务台处理标准

收集员工号、办公地点、网络类型、VPN 客户端版本、报错截图、目标系统地址和发生时间。单人问题优先排查本地网络和权限；多人问题应升级为网络或内网系统故障。

推荐分类：`technical`。

## 回复模板

您好，请提供员工号、VPN 报错截图、客户端版本、当前网络环境和无法访问的系统地址。我们会核查账号权限、MFA、客户端配置和内网策略，并判断是否需要网络团队介入。

## 升级条件

- 大量员工 VPN 同时失败。
- 生产、财务、人事等关键系统无法访问。
- 远程办公期间影响客户交付或紧急发布。

## 云舟科技网络说明

- VPN 客户端：YunVPN。
- 远程办公认证：CloudID 账号 + MFA。
- 办公网 Wi-Fi：YZ-Office，访客网络为 YZ-Guest。
- 内网 DNS：仅在办公网或 VPN 下生效。
- 生产系统访问：需要额外的系统权限和安全审批，不因 VPN 连通自动开放。

## 排查矩阵

| 现象 | 可能原因 | 服务台动作 |
| --- | --- | --- |
| VPN 无法登录 | 密码错误、MFA 失败、账号未授权 | 核查 CloudID 和 VPN 用户组 |
| VPN 登录后打不开系统 | 系统权限缺失、DNS 异常、路由策略 | 收集目标 URL 和错误截图 |
| 办公网频繁掉线 | AP 覆盖、终端驱动、网络拥塞 | 收集楼层、座位号和设备型号 |
| 只能访问部分系统 | 权限或分段网络策略 | 转 IT 网络组或系统负责人 |
| 手机热点可用、家宽不可用 | 本地运营商 DNS 或代理冲突 | 指引切换 DNS 或关闭代理 |

## 员工自助检查清单

- 确认 CloudID 可以正常登录。
- 确认手机 MFA 时间同步且未更换设备。
- 更新 YunVPN 到最新版本。
- 关闭个人代理、加速器或安全软件后重试。
- 记录目标系统地址、错误截图和发生时间。
- 尝试切换网络，例如手机热点，判断是否为本地网络问题。

## 高风险场景

若员工反馈生产系统、财务系统、人事系统或客户交付平台无法访问，服务台应同时核查 VPN、系统权限和应用可用性，不要只按普通网络故障处理。若同一时间多人反馈，应升级为 P1 或 P2。

## 回复模板扩展

您好，请提供员工号、办公地点或远程办公城市、YunVPN 版本、报错截图、目标系统 URL 和发生时间。我们会核查 VPN 授权、MFA、网络路由和目标系统权限，并判断是否需要网络组介入。
