# 知识库维护与 RAG 缺口处理

## 适用场景

- AI 回答“暂无知识库依据”或命中文档明显不相关。
- 员工反复咨询同一问题，但知识库没有标准答复。
- 制度更新后，机器人仍引用旧版本。
- 服务台希望把高频人工答复沉淀为知识文档。

## 维护原则

1. 每篇文档只聚焦一个员工服务主题，标题应包含员工常用问法。
2. 文档必须标明适用场景、入口、处理标准、回复模板和升级条件。
3. 涉及制度、薪酬、财务、安全和劳动关系时，需归口部门审核后发布。
4. 已废止制度应从知识库移除或标注失效，避免 RAG 召回旧口径。
5. 新增文档后应补充检索评测问题，覆盖正式问法和口语化问法。

## RAG 缺口处理

- 无命中：记录员工原问题、期望答案、归口部门和建议文档标题。
- 错命中：记录被召回文档、错误原因、应命中文档和改写建议。
- 旧口径：确认制度版本、发布日期、归口部门和替换范围。
- 敏感问题：不要直接写入未经审核的答案，应转人工审核。

## 服务台处理标准

服务台在人工审核中发现知识缺口时，应把工单标记为“知识库待补充”。系统运维管理端可查看 RAG 召回、Prompt、Token 和 Trace，用于定位检索或提示词问题。

推荐分类：`inquiry`。

## 回复模板

您好，该问题当前缺少可直接采纳的知识库依据，我们会先转人工确认，并将问题沉淀为知识库待补充项。后续同类问题会优先通过钉钉机器人或员工服务台给出标准入口和处理口径。

## 升级条件

- 高频问题连续出现但 RAG 无法命中。
- 知识库引用旧制度导致员工误解。
- AI 建议涉及敏感承诺或可能绕过审批。

## 云舟科技知识库角色

| 角色 | 职责 |
| --- | --- |
| 服务台运营 | 收集高频问题、整理初稿、维护关键词 |
| 归口部门 | 审核制度口径和办理流程 |
| 系统运维管理端 | 查看 RAG、Prompt、Token、Trace 和状态机 |
| 服务台人员 | 在人工审核中反馈知识缺口和错误命中 |
| 安全负责人 | 审核敏感数据、AI 工具和权限边界文档 |

## 文档模板

每篇知识文档建议包含以下结构：

1. 文档信息：编号、版本、归口部门、适用范围。
2. 适用场景：员工会怎么问。
3. 员工自助路径：在哪里查、在哪里办。
4. 服务台处理标准：收集哪些材料、如何分流。
5. 风险边界：哪些不能承诺、哪些必须人工。
6. 回复模板：可直接用于工单回复。
7. 升级条件：何时 P1/P2 或转专业团队。

## RAG 评测样本要求

新增或修改知识文档后，应补充至少 2 条检索评测问题：

- 一条正式问法，例如“加班餐补发放条件是什么？”
- 一条口语问法，例如“昨晚加班有饭补吗？”

评测样本应指向文档逻辑 ID，并在入库后替换为真实 doc_id 和 chunk_index。

## 知识缺口闭环流程

1. 服务台在人工审核中标记“知识库待补充”。
2. 运营人员汇总同类问题，判断是否需要新文档或更新旧文档。
3. 归口部门审核答案边界。
4. 系统运维管理端观察 RAG 命中和 Token 消耗。
5. 更新评测样本并回放失败问题。

## 常见质量问题

- 文档只有制度结论，没有入口和材料清单。
- 标题过于正式，缺少员工口语关键词。
- 多个主题混在一篇文档，导致 RAG 命中不稳定。
- 制度版本过期但未标注。
- 回复模板承诺了归口部门未确认的结果。
